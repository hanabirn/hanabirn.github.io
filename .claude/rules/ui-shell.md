# Page shell, navigation, header, rails, mascot, tour, changelog, theme, PWA

(Moved verbatim from CLAUDE.md on 2026-10-24; keep it up to date when changing these files.)

- The site used to be on Netlify (`hanabirn.netlify.app`), which is now paused for exceeding its free usage limits. All Netlify config (`netlify.toml`, the empty `netlify/functions` dir, the local `.netlify` CLI cache) was removed in the 2026-09-24 cleanup, along with the stale `hanabirn.netlify.app` URLs in `index.html`'s OG/Twitter meta tags. Don't reintroduce Netlify-specific files or URLs — with one deliberate exception: Netlify built `hanabirn.netlify.app` from this repo's `main` (since 2026-10-08 its builds are **Stopped** in the Netlify dashboard so pushes don't use its free credits — the last deploy, with `_redirects`, keeps serving; changing `_redirects` means switching builds back to Active first), and visitors kept using it (an iPhone home-screen app installed from there got 403 from the AI Worker, which only allows `hanabirn.xyz`), so the root `_redirects` file 301s every path there to `https://hanabirn.xyz/…?from=netlify` (added 2026-10-03 at the owner's request); that marker makes `js/widgets.js` show the "網站搬家囉" notice (`#moved-overlay`: delete the old home-screen app and install again, offering `openInstallHelp()`) and is then removed from the address bar. Progress stored under the Netlify origin can't follow; the notice says so. GitHub Pages runs Jekyll, which skips `_`-prefixed files, so it has no effect on the real site.

**Single-page app shell**: `index.html` contains every "page" (`#page-home` — the default — plus `#page-quiz`, `#page-notes`, `#page-about`, `#page-guestbook`, `#page-feedback`) as sibling `<div>`s toggled via `display: none/block`. `switchPage(page, el)` in `js/quiz.js` handles navigation — no router, no URL state. Every page has a `.nav-btn[data-tab=…]` on desktop **and** in the phone UI. **Navigation (reorganised 2026-10-10 to keep the screen simple):** the desktop header (owner's layout 2026-10-23, option C of tools/.mockups/backdrop/header.html) is a grid of three rows: a thin bar of controls on top, right-aligned with a dashed line under it (learning pill, language, theme switch, account pill, ☰), the brand (mascot + a larger site name) centred, and `.main-nav` centred below with larger buttons (css/header.css); `headerFit()` in `js/widgets.js` now only shortens the phone title. `.main-nav` holds 首頁 / 單字測驗 / 複習 (2026-10-17; it was 檢定考試, now a tab of the 單字 page) and two dropdowns (`.nav-group`, opened by hover with a mouse or a click: `toggleNavGroup()`): **學習 ▾** (`#nav-group-learn`: 文法, 閱讀, 聽解) and **工具 ▾** (`#nav-group-tools`: 字典, 字母表, 記事本), each item with a one-line description (`nav_<page>_desc`). The ☰ (`#site-menu`, `toggleSiteMenu()`) holds 更新內容, the tour, 下載 App, 留言板, 建議&改進, 關於我, the BGM player (its markup lives there, laid out by `.menu-bgm`), 顯示設定 and 重新整理 — so the only floating button left on desktop is 小花火 (the clock widget and the floating settings / reload buttons were removed). A dropdown gets `.has-active` when one of its pages is open. Phones (≤768px): the header keeps language + an icon-only account button; the bottom `.tabbar` is 首頁 / 單字 / 複習 / **學習** / 更多 — 學習 opens `#learn-sheet` (three cards with progress, `renderLearnSheet()` counting passed items in `grammar_progress` / `reading_progress` / `listening_progress`), 更多 opens `#more-sheet`, a grid in groups (工具 / 網站 / 交流) plus a quick row (深色模式, 背景音樂, 顯示設定, 重新整理). `LEARN_TABS` / `MORE_TABS` in `js/quiz.js` say which tab lights up. Changelog: `js/updates.js`, the `SITE_UPDATES` popup (760px wide on computers, a ✕ in a sticky title row — on phones it replaces the 關閉 button), `UPDATES_PER_PAGE` (4) entries a page with 上一頁 / 下一頁 and ← → — add an entry in all 9 languages when shipping something visible; a dot (`.updates-dot`, on the ☰, its item, the 更多 tab and its tile) shows until it's opened. `switchPage()` sets `.active` by `data-tab`, not on the clicked element, so all copies stay in sync, and tab visibility (`applyTabVisibility`) hides every copy (and a dropdown / the 學習 tab whose pages are all hidden). It shows a page by clearing its inline `display` (not setting `block`, so a page's CSS can make it a grid) and puts the page on `body[data-page]`; `css/base.css` uses that to widen the alphabet, dictionary and quiz pages to 1180px on screens ≥1024px (on the quiz page only `#path-card` takes the width). Desktop layouts there: the alphabet shows 6 cards a row (kana as a 5-column 五十音 chart with `.alpha-blank` gaps), the dictionary is a 2-column grid (`#dict-results` is `display: contents`; examples on the right), and the path shows the picked unit's levels beside a sticky unit list (`.path-wide`; phones keep the `<details>` accordion, `.path-accordion`). Home is locked visible. There is no guide page any more: new visitors get the tour below. All CSS is split by feature into `css/*.css` and all linked individually in `<head>` (no bundling), and `js/*.js` files are loaded as plain `<script>` tags in a specific dependency order at the bottom of `<body>` (theme → mascot → PapaParse CDN → `js/i18n.js` → the 9 `i18n/<lang>.js` dictionary files → speech → quiz → learnlang → path → home → practice → account → dict → alphabet data → alphabet → grammar → reading → listening → updates → tour → rails → guestbook → notes → feedback → widgets). New JS files must be added to that script list, to `service-worker.js`'s `ASSETS` cache list, and CSS files to both `<head>` and `ASSETS`.

**Learning language (`js/learnlang.js`, 2026-10-17, proposal A)**: one choice for the whole site — the header pill `#learn-pill` ("🇯🇵 日文 ▾", menu `#learn-pill-menu` grouped by `LANG_REGIONS`, with a 最近 row from `learn_lang_recent` and a 🌐 網站文字 button) sets `localStorage.learn_lang` (`ja ko zh en fr ru es de`, synced as a raw key); `learnLang()` reads it, guessing from `last_quiz_set` / `grammar_set` before a first choice, and pages with no language show `learnChooseHtml()`. `setLearnLang()` → `learnLangChanged()` sends 文法 / 閱讀 / 聽解 back to their lists and redraws (`refreshDynamicContent`). Followers: the three 學習 pages, the alphabet chart (only that language's tabs, `alphaTabsShown()`), the dictionary's starting language (`dictFollowLearnLang`, its own buttons stay for other lookups) and the rail's word of the day (all 8 languages now; its 日 / 韓 / 英 / 中 chips are gone). On phones the pill takes the UI-language globe's place: `.lang-globe-btn` is hidden but its menu stays and opens from the pill menu or the More sheet's 網站文字 (`openUiLangMenu()`). `LEARN_QUIZ_CODE` maps to the 單字 page's codes (jp, kr …).

**Site tour (`js/tour.js` + `css/tour.css`)**: replaced the old 教學手冊 page (removed 2026-10-03). `TOUR_STEPS` lists each step's i18n key (`tour_<key>_title/_text`) and the elements it may spotlight, best first (desktop nav or its 學習 / 工具 dropdown button or ☰, else the phone tab bar, `#tabbar-learn` or `#tabbar-more`; a step pointing at a menu adds where to look: `tour_in_learn` / `tour_in_tools` / `tour_in_menu` / `tour_in_more`); a step whose targets are all hidden shows a centred card. The spotlight is a fixed box with a huge `box-shadow` that dims everything else; the card goes below the target, else above, else bottom. It starts by itself ~1 s after load only for a first visit (`tourIsFirstVisit`: no `tour_done` and no practice data such as `daily_activity`/`quiz_records`, so existing visitors aren't interrupted) and is replayed via `startTour()` from the settings panel and the phone More sheet. When adding a main feature, add a step in all 9 languages.

**Tooltips (end of `js/widgets.js`)**: native `title` tooltips are an unstylable white box, so on mouse hover a title moves to `data-tip` and a vermilion `.site-tip` bubble shows it (icon-only buttons get the text as `aria-label`). Keep using `title` / `data-i18n-title` in markup; it's picked up automatically.

**Mascot (小花火, `js/mascot.js` + `css/mascot.css`, images in `images/mascot/`)**: the owner's own drawing (a girl in a pink sakura kimono, replaced the SVG firework stand-in 2026-10-04). `tools/split_mascot.py <psd>` splits the owner's Clip Studio PSD into six same-size WebP layers — body, blush (the 腮紅 layers again, doubled, for the shy face), eyes_open / eyes_closed, mouth_smile / mouth_closed — moving the eye and mouth lines that still sit in the PSD's 線搞 / 眉毛 layers into their part; re-run it when the drawing changes (new expressions = new layers there + a part in the script and `MASCOT_PARTS`). Markup uses `<span class="mascot-slot" data-mascot="full|bust">` (filled by `mascotFillSlots()`), scripts use `mascotHtml('full'|'bust')`: `full` is the whole figure (244×491, `--mascot-ratio`), `bust` the head in a circle for spots of 72px and smaller (header brand, assistant button and chat head, tour, practice hub, 間隔複習 page). Every mascot breathes (CSS) and blinks on one shared 250 ms clock; `mascotTalk(el, ms)` flaps the mouth (assistant replies, tour steps) and `mascotHop(el)` jumps (result screens ≥ 60%); the poke faces are classes on `.mascot`: `mc-happy` (eyes closed in a smile), `mc-shy` (blush shown), `mc-angry` (mouth shut, shaking).

**Side rails (`js/rails.js` + `css/rails.css`, added 2026-10-04)**: on wide desktop screens the empty margins beside the 720px column hold `#rail-left` (小花火 standing, full figure) and `#rail-right` (cards), both `position: fixed` below the header — at `--rail-top`, which `railPlace()` sets from the header's real height (it grows when a language wraps the tagline; a fixed offset let the header cover the rails). The speech bubble sits on 小花火's left when there is room (`.bubble-side`), else above her head. They only show where they fit: left ≥ 1280px, right ≥ 1480px (it must clear 小花火's chat button in the bottom-right corner, so it sits at least 112px from the edge and stops 120px above the bottom); on the pages widened to 1180px (alphabet, dict, quiz) left ≥ 1700px and right ≥ 1940px. Breakpoint upper bounds are written like `max-width: 1699.98px` because zoomed browsers have fractional widths that otherwise fall between two rules. Poking her (`pokeClick`): where the click lands in the figure decides the zone (`pokeZone`: face = x .25–.78, y .24–.47; head above; body below), clicks on transparent pixels of body.webp are ignored (`pokeOnFigure`), and a keyboard press pats her head; head → happy + ♪💕, face → shy + ///, body → hop + !, `POKE_ANGRY_AT` (5) pokes within `POKE_WINDOW_MS` → cross (💢, `POKE_ANGRY_MS` without reactions). She says a line from `poke_head` / `poke_face` / `poke_body` / `poke_angry`, and the first time a page is opened in a visit one from its `ctx_*` key (`RAIL_CTX`; guestbook / feedback / about use `ctx_other`). Each of those i18n keys is one string with the lines separated by `|`; they are placeholders until the owner writes her own. Symbols are removed by a timer, not `animationend` (which never fires with reduced motion or in a background tab). The right rail: 每日一字 (`renderRailWord`), a word a day picked from the topic sets by the date (`railTodayWord`), in the header's learning language (else the language of `last_quiz_set`); 🔊 speaks it; the link opens its topic. On the home page (`body.rail-home`) also the last 14 days of `daily_activity` against the daily goal (hidden on screens under 820px tall). (A 今日任務 card was removed 2026-10-17: it repeated the home page's goal and review cards.) While the left rail shows, the small 小花火 in the home greeting card (`.home-mascot`) is hidden (rule in css/rails.css, same breakpoint); phones keep it. `switchPage()` calls `railsOnPage(page)` and `refreshDynamicContent()` calls `renderRails()`; nothing is fetched while the right rail is hidden. On the quiz page only the path is 1180px wide, so the 1180px rail positions apply only while `#path-card` shows (`body.quiz-wide`, toggled by a MutationObserver in rails.js); otherwise she stands beside the 680px cards. Besides pokes she reacts to the quiz (`railReact`, called from `noteCombo()` and `showResults()`): every 5 right in a row (`react_combo`), now and then a miss (`react_wrong`, at most every 15 s), and the result (`react_perfect` / `react_good` / `react_low`); 30% of head/body pokes get a line about the visitor's day instead (`pokeSituation`: `poke_morning` / `poke_night` / `poke_streak` / `poke_due`). `pokeLines()` fills `{n}` in every `|`-separated line itself, because `t()` only replaces the first.

**Widgets (`js/widgets.js`)**: Self-contained, DOMContentLoaded-initialized features: BGM vinyl player (in the ☰ menu; rotating playlist of external mp3 URLs; on touch devices the volume slider is hidden and it plays at full volume so the hardware volume keys control it — `BGM_HARDWARE_VOLUME`; the phone More sheet's 背景音樂 button calls `toggleBgm()` and shows `.on` while playing), the navigation menus (`headerFit`, `toggleNavGroup`, `toggleSiteMenu`, `closeNavMenus`) and the phone sheets (`toggleLearnSheet` / `toggleMoreSheet`; `closeMoreSheet()` closes both). The floating clock + weather widget was removed in the 2026-10-10 navigation clean-up.

**Theming (`js/theme.js`)**: Light/dark theme toggled via `data-theme` attribute on `<html>`, persisted to `localStorage['theme']` (first-time visitors follow `prefers-color-scheme`), applied synchronously before `DOMContentLoaded` to avoid flash; `applyTheme()` also updates `<meta name="theme-color">`. The look is "和紙" (washi paper, light) / "墨夜" (ink night, dark): flat paper background, ink text, a single vermilion accent, Noto Serif TC headings and Noto Sans TC body — no glows, gradients or glassmorphism (the old sakura/stars/particles/fireflies were removed in the 2026-10 redesign); the decoration is a faint 青海波 wave pattern rising from the bottom of the screen (`body::before` in `css/base.css`, colours in `--wave-pattern` in `theme.css`) and, since 2026-10-23 (owner's pick B, tools/.mockups/backdrop/ui.html), a band of 七寶 behind the header fading down (`body::after`, `--shippo-pattern`; the desktop header is slightly see-through with a vermilion bottom line). `body` has `isolation: isolate` so these `z-index: -1` layers paint above its paper colour. Option B also gave the page cards (`.lang-card`, `.mode-card`, `.quiz-card`, …) a 4px vermilion top edge and a soft lifted shadow (`--shadow-card`), section titles inside them a vermilion bar on the left (`.pc-section h4`, `.hub-title`, `.home-section-title`, …, end of the card rules in css/base.css) and two-column pages a dashed line between the columns. All colours are CSS custom properties in `css/theme.css`: prefer the semantic tokens (`--primary`, `--primary-edge`, `--surface`, `--line`, `--edge`, `--ink`, `--success*`, `--danger*`, `--track`, `--font-serif`); the older names (`--accent-pink`, `--text-pink`, …) are kept as aliases so existing rules still work. Buttons are **chunky 3D**: a 2px outline plus a 4px darker "thickness" drawn with `box-shadow: 0 4px 0 var(--edge)` (vermilion buttons use `--primary-edge`), and `:active` does `translateY(4px)` and drops the shadow — box-shadow rather than a border so pressing doesn't change the height and shift the layout. The shared recipe is the "Chunky 3D buttons" block at the top of `css/quiz.css` (`.lang-btn`, `.mode-btn`, `.option-btn`, `.tool-btn`, `.back-btn`, `.next-btn`, `.share-btn`, …). The share card (`shareScoreCard`) is a canvas, which can't read CSS variables, so it hardcodes the light 和紙 palette.

**PWA**: "下載 App" (`.install-entry`: an item in the ☰ menu on desktop and a tile in the phone More sheet; hidden via `html.is-standalone` when running as the installed app) opens `#install-overlay` (`openInstallHelp()` in `js/widgets.js`): browsers with `beforeinstallprompt` get the real install prompt, the rest (iOS Safari, desktop Safari, Firefox) get add-to-home-screen steps for their platform (`INSTALL_STEPS`). The bottom `#pwa-install-banner` (home page only, folds away after `INSTALL_BANNER_MS`) suggests it once (on iOS 8 s after load, never over the site tour); ✕ sets `pwa_install_dismissed`. Chrome on Android fires `beforeinstallprompt` only after a little while on the page, so an already-open dialog swaps its steps for the button when it arrives. iPhone has no install API at all (only the steps). In-app browsers (LINE, Facebook, Instagram, Threads, WeChat, KakaoTalk, TikTok — `inAppBrowser()`) can't install, so the dialog asks to open the site in a real browser: one tap for LINE (`?openExternalBrowser=1`) and on Android (an `intent://` URL to Chrome), steps (`install_inapp_ios`) in iPhone apps. The viewport has `viewport-fit=cover`, so an iPhone home-screen app runs under the status bar: the header pads itself by `env(safe-area-inset-top)` and on phones the header is `position: sticky` with its solid background — iOS 26 blurs the top edge of a home-screen app (it blurred the header row) unless a fixed / sticky box with a background covers it; for the same reason closed overlays (`.updates-overlay`, `.tab-settings-overlay`, `.more-sheet-overlay`) are `display: none`, not invisible full-screen boxes above the header (they fade with `transition-behavior: allow-discrete` + `@starting-style`, end of css/nav.css), and `html` has the paper colour too, fixed menus near the top add it too, and `body` pads the side insets for landscape. `manifest.json` + `service-worker.js` (network-first-with-cache-fallback strategy — `fetch` always hits the network, revalidating same-origin files and pages with `cache: 'no-cache'`, and updates the cache, only falling back to cache when offline). Bumping `CACHE_NAME` is necessary when changing the `ASSETS` list, since a stale cached list would keep serving old files to offline visitors. **The 新版本 banner (`#update-banner`)**: `updatefound` only fires when service-worker.js itself changes, so the inline script at the end of index.html (`watchForDeploy`) also sends a HEAD for `/?deploy=<now>` (the unique query skips the CDN's 10-minute cache) 10 s after load, every 5 min and whenever the tab comes back, and shows the banner when its Last-Modified is newer than `document.lastModified` — GitHub Pages stamps every file with the deploy time, so any push counts.

**Visitor counter (`js/theme.js`)**: the footer counts one visit per device per day (`visit_counted_day`): the first load of the day calls counterapi's `up` on the `daily-visitors` counter (made by the owner 2026-10-22, from 0), later loads only read it. The old `hanabirn` counter counted every load and stopped at about 1,180.
