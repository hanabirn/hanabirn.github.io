# Listening pages

(Moved verbatim from CLAUDE.md on 2026-10-24; keep it up to date when changing these files.)

**Listening (`js/listening.js` + `css/listening.css`, `#page-listening`, added 2026-10-10 — Japanese N5 (6 practice sets × 9), N4 / N3 (3 × 10), N2 / N1 (2 × 10), each with mock exam 1 in the official mix: N5 24, N4 28, N3 28, N2 32, N1 37 questions)**: JLPT-style sets hand-written in `tools/listening/<id>.json` (original content; the exam formats of JLPT, TOPIK, HSK 3.0, TOEIC, TOEFL 2026, DELF, DELE, Goethe and ТРКИ are summarised in `tools/listening/EXAMS.md` — follow it when adding a language or level). A level file lists its item types in exam order (`types`, default task / point / utterance / response; the 問題 number is the position — N3 adds `outline`, N2/N1 use task / point / outline / response / integrated), plus `mock_plays` (1), `mock_counts` (the official mix in questions, checked) and `read_secs` (10). Item types: `task` 課題理解 / `point` ポイント理解 (picture options are one 2x2 sheet: each option is an `<img>` twice the box's size moved by `LISTENING_PIC_QUARTERS` — a CSS-background crop came out blank on the owner's phone; the question shows on screen, and the player pauses after the first line for `read` seconds — "看選項的時間" with 跳過 in practice) — 4 printed options `{t, emoji, zh, en}`; `outline` 概要理解 (4 spoken options, nothing shown first); `utterance` 発話表現 (needs a `scene` {emoji, zh, en}; only its emoji shows until answered, since its text translates the spoken question) / `response` 即時応答 — 3 spoken options `{who, s, zh, en}`, read aloud with their number — since 2026-10-22 the number is the narrator's own clip (`na` / `nk`, `NUMBERS` in build_listening.py) played with `LISTENING_NUMBER_GAP_MS` before the option, so the two don't run together; `integrated` 統合理解 (printed or `spoken` options). An item has `options` / `answer` / `explain`, or `questions: [{q, spoken?, options, answer, explain}]` for several questions about one recording (統合理解's last item, HSK 4+, TOEIC Part 3/4, TOPIK 25–30) — each `q` is a spoken question played after the lines. `lines` = `{who: N|F|M|F2|M2, s, zh, en}` played in order (F2 / M2: a third speaker); optional glossary `words` underlined in the transcript; a practice set should hold every type of its level. Sets with `"mock": true` are mock exams: types in exam order and the official count. Built by `python tools/build_listening.py` into `data/listening/<id>.json` (items normalised to `questions[]`) + `index.json`, with furigana and glossary checks from build_reading's `sentence()` and zh-Hans added. It also renders the audio with Google Cloud TTS, one voice per speaker (`VOICES`: ja narrator Chirp3-HD-Kore, woman Erinome, man Charon — picked by the owner; F2 Leda, M2 Fenrir), spoken from the kana, into `data/audio/listening/<lang>/<a>.mp3`, `a` = audio_id("who|plain|said") stored in the data (the page never computes it); `--no-audio` skips it. Don't edit `data/listening/` by hand; the source JSON layout (2-space indent, leaf objects on one line) should be kept when a script writes it. The page: level chips → a 模擬考 card (mock sets) and the practice sets (score per set, exam-mode switch `listening_exam`) → one item at a time (big ▶ playing the item's chain of recordings with `audioPlaying` set so `stopSpeech()` stops it; the browser voice when a file is missing; practice: unlimited plays, 🐢 0.8× `listening_slow`, 👀 peek, the answer right away (a multi-question item once every question is picked); exam mode: `LISTENING_EXAM_PLAYS` (2), no slow, no peek; mock exam: the item plays by itself once, then an answer countdown (`LISTENING_ANSWER_SECS` per question) moves on by itself — an unanswered question is stored as -2 —, picks can change until then, no answers until the end) → result (score per type counted in questions, time, average plays; a mock exam adds an answer sheet whose cells open the item in review (`listeningReviewMock`); `LISTENING_PASS` 2/3 saves the best in `listening_progress`, synced; a retry of the missed items doesn't count) → 生詞小複習 like the 閱讀 page (`LISTENING_WORD_SET` ja_n5 → jlpt_n5). `switchPage()` calls `listeningStop()` (which also stops a 閱讀 read-all and the countdown). Answers count toward `daily_activity` (a mock exam's when it ends). In the 學習 ▾ dropdown and the phone 學習 sheet, tour step `tour_listening_*`, 小花火 line `ctx_listening`. Not to be confused with the word-level 聽力測驗 tool in the practice hub (js/quiz.js). When testing in a signed-in browser, don't finish sets with made-up answers: `listening_progress` and `daily_activity` sync with merge rules that keep the best / the max, so a fake score can only be removed by rewriting the cloud copy (`fsPut`).
