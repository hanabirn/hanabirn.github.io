# Accounts and sync, friends, push reminders, guestbook

(Moved verbatim from CLAUDE.md on 2026-10-24; keep it up to date when changing these files.)

**Guestbook (`js/guestbook.js`, Worker side `worker/assistant/src/guestbook.js`, rebuilt 2026-10-08)**: served by the `hanabi-assistant` Worker at `/guestbook` (`GUESTBOOK_API`; `localhost:8787` locally) and stored in its KV namespace `GUESTBOOK` (`list` = all messages newest first, `u:<uid>` = that account's message), which only the Worker can write — so the rules really hold. Posting needs a site account: the client sends the Firebase ID token, the Worker checks it with the Identity Toolkit (`FIREBASE_API_KEY`, the public web key), refuses email accounts whose address isn't verified (the gate offers 寄驗證信 via `sendEmailVerification`), allows **one message per account** (the mark stays even if the owner deletes the message) and has Gemini (`moderate()`, lite model first, JSON schema) refuse violence, politics, sexual content, hate, spam/ads and personal data — failing closed (`moderation_busy`) when no model answers. Friendly mentions of a country ("台灣加油") are explicitly not politics. `renderGuestbookGate()` shows sign in / verify / already posted / the form; `account.js` calls `guestbookOnUser()` on sign-in changes. The owner deletes a message with `DELETE /guestbook/<id>` + `Authorization: Bearer <ADMIN_TOKEN secret>`. The old Apps Script guestbook (5 messages) was imported into KV; the 建議&改進 page still uses Apps Script.

**Friends (`js/friends.js` + `css/friends.css`, `#page-friends`, Worker side `worker/assistant/src/friends.js`, 2026-10-23, owner's plan B after looking at Duolingo)**: served by the `hanabi-assistant` Worker at `/friends` (`FRIENDS_API`, `localhost:8787` locally) and stored in the D1 database `FRIENDS` (`hanabi-friends`, tables in `worker/assistant/schema.sql`: `profiles`, `links` (a friendship or request, a < b, with the 🤝 pair columns), `notes` (cheers / nudges, one of each kind per sender, receiver and day)). One `POST /friends {action}` with the Firebase ID token (checked like the guestbook's, `firebaseUser` / `bearer` exported from src/guestbook.js, cached 5 min) returns the whole state: `get`, `profile` (display name — moderated with the guestbook's `moderate()` — and `public`), `ping` (the device's streak, words this week, learning languages, practised today; `friendsActivity()` sends it `FRIENDS_PING_MS` after `logDailyActivity()`, only once `friends_on` says this account opened the page), `add` / `respond` / `remove` (friend codes, 8 characters without 0 O 1 I L, shown HANA-7K3P; a request the other side already sent is accepted), `pair` (🤝 invite / accept / leave, at most 5; grows by one on a Taiwan day (UTC+8) both practised, 0 after a missed day), `send` (a fixed sticker, `fr_cheer_0…5` / `fr_nudge_0…5` — no free text, so nothing else to moderate; a nudge only while the friend hasn't practised today), `seen`. Avatars (owner's pick C): one of 24 icons (`FRIEND_AVATARS`) on one of 6 colours (`FRIEND_AVATAR_COLOURS`), stored as `profiles.avatar` "icon:colour" (counts mirrored by `AVATAR_ICONS` / `AVATAR_COLOURS` in the Worker) — no uploads, so nothing to moderate; picked by tapping my avatar (`friendsAvatarPickerHtml`); none picked = the name's first letter. Other visitors only ever see the code, name and avatar, the numbers only when `public` (off by default); never the uid. The D1 database is `hanabi-friends` in APAC (id in wrangler.jsonc, created 2026-10-23). Limits: 50 friends + requests, 20 requests a day, `FRIENDS_LIMITER` 30/min. The page: two columns on computers (1180px; left: my card — code, share, the box for a friend's code (`friendsAddRowHtml`), the public switch — then 🤝 and the notes; right: requests (a vermilion box, only when there are some) above the weekly leaderboard — sortable by words or streak, a sticker menu under a row, and a 管理 switch (`friendsManage`) that puts 刪除 on each friend's row; owner's request 2026-10-23), on phones a strip, the newest note and the tabs 排行榜 / 🤝 連續 / 加好友 (`friendsPhone()`); a shared link `?friend=CODE` opens it with the code filled in; removing a friend takes two presses (no browser dialog). Unread notes show as `#home-friends-card` on the home page and `.friends-dot` on the ☰ item / More tile (`friends_unseen`). Explained in privacy.html section 4 (`sa_p3`). **Local test**: `wrangler d1 execute hanabi-friends --local --file=schema.sql`, `FRIENDS_TEST=1` in `.dev.vars` lets the local Worker take `X-Test-User: <name>` instead of a token, and on localhost `localStorage.friends_test_user` makes the page send it — neither works on the deployed Worker / site. Push reminders (item 20) will also carry nudges.

**Daily reminders — Web Push (`js/push.js`, Worker side `worker/assistant/src/push.js` + `push_text.js`, 2026-10-24, owner's plan item 20)**: the 設定 panel's 🔔 每日提醒 section (`renderPushSettings`, called by `toggleTabSettings`) turns reminders on per device: `Notification.requestPermission`, `pushManager.subscribe` with the VAPID public key (`PUSH_VAPID_PUBLIC`, the same as `VAPID_PUBLIC` in wrangler.jsonc; the private half is the Worker secret `VAPID_PRIVATE`, locally in `.dev.vars`), then `POST /push {action: subscribe, sub, hour (19–22, owner's pick, default 20), tz, lang, streak, practised, day}` — with the Firebase ID token when signed in, so the row carries the uid. `logDailyActivity()` calls `pushActivity()` (once a local day: `practised`), sign-in changes `pushOnUser()`. Stored in D1 `push_subs` (same database as 好友, schema.sql). The Worker's cron (`"triggers": {"crons": ["0 * * * *"]}`, `scheduled` → `runReminders`) sends to each device whose local hour it is, that hasn't practised that local day and hasn't been reminded that day (owner's pick: only when not practised); a friend's 🔔 nudge (`pushNudge`, from src/friends.js `send`) goes at once to that account's devices. Sending is RFC 8291 aes128gcm + RFC 8292 VAPID with WebCrypto only (no packages); 404/410 from the push service deletes the row; `test` sends a test notification (3 an hour). Texts in 9 languages in src/push_text.js (the nudge lines copied from `fr_nudge_*` — keep them in step). service-worker.js shows the notification (`push`) and a tap opens / focuses the site (`notificationclick`; a nudge opens `/?page=friends`, handled in js/friends.js). iPhone: only the home-screen app (iOS 16.4+), the section says so. Local test: `wrangler dev --test-scheduled`, then `curl localhost:8787/cdn-cgi/handler/scheduled` runs the cron.

**Accounts & sync (`js/account.js` + `css/account.css`, added 2026-10-04)**: optional sign-in (Google popup, or email + password with sign-up / reset) through Firebase project `hanabi-site` (Spark plan; Auth providers Google + Email/Password; authorized domains include `hanabirn.xyz` and `localhost`; Firestore in `asia-east1` with owner-only rules `match /users/{uid}/{document=**} { allow read, write: if request.auth.uid == uid }`). The web config in `FIREBASE_CONFIG` is public by design. Only the Auth SDK is loaded (dynamic `import()` from gstatic, pinned version in `FIREBASE_SDK`), and only when the account dialog opens or `localStorage.acct_signed_in` says this device was signed in; Firestore is used through its REST API with the user's ID token (`fsRequest`) instead of the 680 KB SDK. Each key in `SYNC_KEYS` is one document `users/{uid}/data/{key}` = `{v: <localStorage string>}`, merged with its own rule (`syncMerge`: unions / newer entry / max, scalars keep this device's value) — on sign-in for every key (`acctFullSync`), afterwards for keys written since (a wrapped `Storage.prototype.setItem` marks them; uploaded `SYNC_DEBOUNCE_MS` after the last change and when the page is hidden). Not synced: the notepad's attachments, `quiz_cache_*`, device prefs (the notepad's notes and folders are, since 2026-10-17). Add a key to `SYNC_KEYS` (with a merge rule) when a new feature stores progress worth keeping. Sign-out keeps the device's data; "delete account" removes the cloud docs and then the user (needs a sign-in within the last few minutes). UI: `.account-entry` in the header (a pill with the name on desktop, an icon on phones), `#home-account-card` (hidden when signed in), `#account-overlay`. Explained to visitors in privacy.html section 4 (`sa_*` keys in js/privacy.js).
