# Grammar pages

(Moved verbatim from CLAUDE.md on 2026-10-24; keep it up to date when changing these files.)

**Grammar (`js/grammar.js` + `css/grammar.css`, `#page-grammar`, added 2026-10-08 — Japanese N5 (62 points), N4 (59), N3 (60), N2 (76), N1 (67) (2026-10-16), Korean 1급 (34), 2급 (35), 3급 (37), 4급 (35), 5급 (30), 6급 (30) (2026-10-17) — graded 2026-10-16 by the national standard curriculum's levels 1–6 (owner's pick; they were TOPIK I / II, ids ko_topik1/2: `GRAMMAR_KO_MOVED` / `grammarMoveKo()` in js/grammar.js move old progress keys, also in account.js's sync merge; a level named "N급" shows as `learn_level_n` — "1 級", "Level 1" — on the site and in the Discord bot), French A1 (26), A2 (30), Russian A1 (24), A2 (30) (Russian examples with a stressed reading; check new ones against Wiktionary with the git-ignored tools/.vocab-cache/ru_stress_check.py) and Chinese HSK 1–2 (30) and HSK 3 (30, examples with pinyin and zhuyin — the build derives the zhuyin from the hand-written pinyin syllable by syllable (`tools/zh_reading.py`: `zhuyin()`, neutral-tone dot first, Taiwan style) and refuses a sentence that doesn't line up; the quiz sentences (plus `full_reading`, the sentence with the answer in it, shown once answered, since 不 / 一 change tone there), options and common mistakes get generated pinyin (`reading()`: words the examples spell are spelled the same way, then pypinyin with neutral particles and 一 / 不 sandhi; fix a word in `WORDS`, a whole line in `OVERRIDES` or in the source as `q_reading` / `options_reading` / `wrong_reading` / `right_reading` / `full_reading`) — review the printed readings after adding Chinese points; the page has a 拼音 / 注音 / 兩者 switch, `grammar_zh_reading`, also above the quiz), each with notes and common mistakes)**: lessons are hand-written in `tools/grammar/<id>.json` (`{id, lang, level, order, points: [{id, pattern, title, form, explain, examples: [{ja, kana, zh, en}] (Japanese; other languages {text, zh, en}, optional reading — `exText()` / `exReading()`), quiz: [{q, zh, en, options[4], answer}]}]}`, texts as `{zh, en}`) and built by `python tools/build_grammar.py` into `data/grammar/<id>.json` + `index.json` (levels sorted by `order`, easiest first — the page opens the first one; points may also have `notes: [{zh, en}]` and `mistakes: [{wrong, right, zh, en}]`, and the build refuses a Chinese note left inside a Japanese `wrong` / `right`); the script checks them and adds `zh-Hans` (OpenCC tw2sp) — don't edit `data/grammar/` by hand. Explanations and examples must be our own (other sites' texts are copyrighted; which grammar belongs to which level is fair to follow). `gText()` picks zh / zh-Hans / en (other UI languages read English); `gHint()` shows the English translation / quiz hint for the Chinese lessons in a Chinese UI (the Chinese one would repeat the sentence and give the answer away). The build skips source files with no points yet and orders languages 日 韓 英 中 法 俄 西 德. The list shows `GRAMMAR_PER_PAGE` (5) points a page with 上一頁 / 下一頁 (returning from a point opens its page). On screens ≥1024px a point is two columns — form, explanation, notes and mistakes left, examples and the practice button right (sticky) — on a 1180px page (`body.grammar-wide`, also in css/base.css and the rail rules in css/rails.css); phones keep one column. A point: pattern, title, form (接續), explanation, examples with 🔊 (recorded: `build_audio.py` renders each Japanese `ja|kana`, spoken from the kana, and each Korean / French / Russian / Chinese `text` — Chinese in both accents, played with `speakChinese()` and a 🔊 台灣 / 中國大陸 switch beside the 拼音 / 注音 one), then its questions — the easy ones shuffled, then the hard ones (`"hard": true`, tagged 進階) shuffled; `GRAMMAR_PASS` (2/3) right marks it learned in `grammar_progress` (synced, best score kept). **Hard questions and sentence ordering (2026-10-16, owner's design):** every Japanese point has 3 easy + 3 hard questions (2 harder fill-ins with harder vocabulary and look-alike patterns as distractors, 1 ordering question); other languages still have 3. An ordering question is `{"type": "order", before, parts[4] in the right order, after, star, alts?}` — the build adds `q` (before ＿＿ ＿＿ ＿★＿ ＿＿ after), `options` (= parts) and `answer` (= star) so the Discord bot and `grammar_why.py` treat it as a 4-option question; the page asks it as the level's `order_style`: `"arrange"` (N5–N4: tap all four parts into order; `alts` lists other valid orders) or `"star"` (N3+, the default: pick the ★ part as in the JLPT); a question's own `"style"` overrides the level's — Korean 1급–2급 are `arrange` with 3 hard questions a point, and from 3급 every point has 4 (2 fill-ins + one `arrange` + one `star`, owner's pick 2026-10-17). Japanese is free in word order, so an ordering question must have one valid order — or, for `star`, the ★ part must sit in the same place in every valid order; and every distractor must be unacceptable Japanese in context (scan the why-explanations for “也可以 / also correct” after generating them). Japanese quiz texts may carry furigana as `漢字{かな}` (same rule as tools/reading/: the kanji run right before the braces); the build keeps the plain text and adds `q_furi` / `options_furi` / `before_furi` / `after_furi` / `parts_furi` segments, drawn as `<ruby>` (`grammarFuri`). N3 and up use kanji, furigana on the harder words. `grammar_why.py` writes one line for an ordering question (why the parts go in that order) and runs the source through `prepare_quiz()` first so its keys match the build. Answers count toward `daily_activity`. In the 學習 ▾ dropdown and the phone 學習 sheet. It has a site-tour step (`tour_grammar_*`) and is in the 小花火 persona's feature list.
