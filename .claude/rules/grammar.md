A point: pattern, title, form (接續), explanation, examples with 🔊 (recorded: `build_audio.py` renders each Japanese `ja|kana`, spoken from the kana, and each Korean / French / Russian / Chinese `text` — Chinese in both accents, played with `speakChinese()` and a 🔊 台灣 / 中國大陸 switch beside the 拼音 / 注音 one), then its questions — the easy ones shuffled, then the hard ones (`"hard": true`, tagged 進階) shuffled; `GRAMMAR_PASS` (2/3) right marks it learned in `grammar_progress` (synced, best score kept). **Hard questions and sentence ordering (2026-10-16, owner's design):** every Japanese point has 3 easy + 3 hard questions (2 harder fill-ins with harder vocabulary and look-alike patterns as distractors, 1 ordering question); other languages still have 3. An ordering question is `{"type": "order", before, parts[4] in the right order, after, star, alts?}` — the build adds `q` (before ＿＿ ＿＿ ＿★＿ ＿＿ after), `options` (= parts) and `answer` (= star) so the Discord bot and `grammar_why.py` treat it as a 4-option question; the page asks it as the level's `order_style`: `"arrange"` (N5–N4: tap all four parts into order; `alts` lists other valid orders) or `"star"` (N3+, the default: pick the ★ part as in the JLPT); a question's own `"style"` overrides the level's — Korean 1급–2급 are `arrange` with 3 hard questions a point, and from 3급 every point has 4 (2 fill-ins + one `arrange` + one `star`, owner's pick 2026-10-17). Japanese is free in word order, so an ordering question must have one valid order — or, for `star`, the ★ part must sit in the same place in every valid order; and every distractor must be unacceptable Japanese in context (scan the why-explanations for “也可以 / also correct” after generating them). Japanese quiz texts may carry furigana as `漢字{かな}` (same rule as tools/reading/: the kanji run right before the braces); the build keeps the plain text and adds `q_furi` / `options_furi` / `before_furi` / `after_furi` / `parts_furi` segments, drawn as `<ruby>` (`grammarFuri`). N3 and up use kanji, furigana on the harder words. `grammar_why.py` writes one line for an ordering question (why the parts go in that order) and runs the source through `prepare_quiz()` first so its keys match the build. Answers count toward `daily_activity`. In the 學習 ▾ dropdown and the phone 學習 sheet. It has a site-tour step (`tour_grammar_*`) and is in the 小花火 persona's feature list.
