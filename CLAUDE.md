# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Hanabiの小天地" — a static, single-page personal website (vocabulary quiz app, guestbook, about page) in Traditional Chinese with 9-language i18n (zh/zh-Hans/en/ja/ko/ru/fr/es/de), focused on vocabulary review and language learning. No framework, no build step, no bundler, no package.json. Plain HTML/CSS/JS served directly.

## Running / deploying

There is no build or test command — the repo root is served as-is by **GitHub Pages**.

- The remote is `github.com/hanabirn/hanabirn.github.io` (a GitHub Pages *user site*), served at the custom domain **`https://hanabirn.xyz/`** straight from the `main` branch root. Pushing to `main` is the deploy — there is no CI workflow, no build step, and no `.github/` directory.
- The custom domain is set by the `CNAME` file at the repo root — don't delete or rename it, or GitHub Pages drops the domain. `hanabirn.github.io` 301-redirects to `hanabirn.xyz`, so old links still work. DNS lives in Cloudflare (GitHub's four apex A + four AAAA records) with the **proxy deliberately off**: behind Cloudflare's orange cloud GitHub can't complete its HTTPS certificate challenge.
- Absolute URLs that name the host — the canonical link and OG/Twitter meta tags in `index.html`, `sitemap.xml`, `robots.txt` — use `https://hanabirn.xyz/`. Use that domain (not `hanabirn.github.io`) for any new absolute URL.
- Because the site is served from the domain root, absolute paths (`/icons/...`, `manifest.json`'s `start_url: "/"`) work as-is; no base-path rewriting is needed.
- The site used to be on Netlify (`hanabirn.netlify.app`), which is now paused for exceeding its free usage limits. All Netlify config (`netlify.toml`, the empty `netlify/functions` dir, the local `.netlify` CLI cache) was removed in the 2026-09-24 cleanup, along with the stale `hanabirn.netlify.app` URLs in `index.html`'s OG/Twitter meta tags. Don't reintroduce Netlify-specific files or URLs — with one deliberate exception: Netlify still builds `hanabirn.netlify.app` from this repo's `main`, and visitors kept using it (an iPhone home-screen app installed from there got 403 from the AI Worker, which only allows `hanabirn.xyz`), so the root `_redirects` file 301s every path there to `https://hanabirn.xyz/…?from=netlify` (added 2026-10-03 at the owner's request); that marker makes `js/widgets.js` show the "網站搬家囉" notice (`#moved-overlay`: delete the old home-screen app and install again, offering `openInstallHelp()`) and is then removed from the address bar. Progress stored under the Netlify origin can't follow; the notice says so. GitHub Pages runs Jekyll, which skips `_`-prefixed files, so it has no effect on the real site.
- There is no linter or test suite configured.

## Architecture

**Single-page app shell**: `index.html` contains every "page" (`#page-home` — the default — plus `#page-quiz`, `#page-examquiz`, `#page-notes`, `#page-about`, `#page-guestbook`, `#page-feedback`) as sibling `<div>`s toggled via `display: none/block`. `switchPage(page, el)` in `js/quiz.js` handles navigation — no router, no URL state. Every page has a `.nav-btn[data-tab=…]` in the desktop `.main-nav` **and** in the phone UI (bottom `.tabbar` for home/quiz/exam/notes, the "More" bottom sheet for dict/alphabet/guestbook/feedback/about, plus 更新內容, the tour replay, settings and reload); "關於我" is not in the desktop nav but a `.header-btn` in the header, next to "更新內容" (`js/updates.js`: the `SITE_UPDATES` changelog popup — add an entry in all 9 languages when shipping something visible; a dot shows until it's opened). On phones both header buttons are hidden and live in the More sheet. `switchPage()` sets `.active` by `data-tab`, not on the clicked element, so all copies stay in sync, and tab visibility (`applyTabVisibility`) hides every copy. It shows a page by clearing its inline `display` (not setting `block`, so a page's CSS can make it a grid) and puts the page on `body[data-page]`; `css/base.css` uses that to widen the alphabet, dictionary and quiz pages to 1180px on screens ≥1024px (on the quiz page only `#path-card` takes the width). Desktop layouts there: the alphabet shows 6 cards a row (kana as a 5-column 五十音 chart with `.alpha-blank` gaps), the dictionary is a 2-column grid (`#dict-results` is `display: contents`; examples on the right), and the path shows the picked unit's levels beside a sticky unit list (`.path-wide`; phones keep the `<details>` accordion, `.path-accordion`). Home is locked visible. There is no guide page any more: new visitors get the tour below. All CSS is split by feature into `css/*.css` and all linked individually in `<head>` (no bundling), and `js/*.js` files are loaded as plain `<script>` tags in a specific dependency order at the bottom of `<body>` (theme → PapaParse CDN → `js/i18n.js` → the 9 `i18n/<lang>.js` dictionary files → speech → quiz → path → home → practice → account → dict → alphabet data → alphabet → updates → tour → guestbook → notes → feedback → widgets). New JS files must be added to that script list, to `service-worker.js`'s `ASSETS` cache list, and CSS files to both `<head>` and `ASSETS`.

**i18n (`js/i18n.js` + `i18n/<lang>.js`)**: `js/i18n.js` only declares `const I18N = {}` plus the shared logic (`applyLang`, `setSiteLang`, `t`); the actual translations live in one file per language — `i18n/zh.js`, `i18n/zh-Hans.js`, `i18n/en.js`, `i18n/ja.js`, `i18n/ko.js`, `i18n/ru.js`, `i18n/fr.js`, `i18n/es.js`, `i18n/de.js` — each just assigning a flat dict to `I18N.<lang>` (e.g. `I18N.en = {...}`; Simplified Chinese needs bracket syntax, `I18N['zh-Hans'] = {...}`). `zh-Hans.js` was generated from `zh.js` with OpenCC (`tw2sp`) and then hand-fixed for mainland wording (单词, 复制, 置顶, 离线, 导航栏, Google 表格…) — when adding a zh key, write the Simplified version by hand in the same style rather than a character-by-character conversion. These must load as `<script>` tags *after* `js/i18n.js` (which declares `I18N`) and *before* any script that calls `t()`/`applyLang()` at top level. `applyLang(lang)` walks all `[data-i18n]` / `[data-i18n-placeholder]` elements and swaps text/placeholders; `t(key, params)` is used for dynamically-generated strings (e.g. `t('load_success', {n: 5})`, using `{n}`-style placeholder substitution). Adding UI text means adding the key to **all 9** `i18n/<lang>.js` files. `setSiteLang()`/`applyLang()` persists choice to `localStorage['site_lang']` and calls `refreshDynamicContent()` (in `js/quiz.js`) so already-rendered dynamic content (quiz menus) re-renders in the new language.

**Word sets (`data/vocab/*.json`, built by `tools/build_vocab.py`)**: the quiz, paths, flashcards and listening tool load bundled, graded word lists — `en_jh` / `en_sh` (大考中心 7000 Level 1–2 / 3–6), `en_toeic` (TSL), `en_toefl` (ECDICT toefl tag minus the 國中 words), `jlpt_n5`…`jlpt_n1` and `topik_1`…`topik_4` (the owner's own sheets), `hsk_1`…`hsk_7` (HSK 3.0, Nov-2025 revision; 7 = 7–9). Each list is ordered easy-first by frequency, which is what makes the first path levels easy. **Don't edit the JSON by hand** — fix `tools/build_vocab.py` and re-run it (`pip install wordfreq opencc-python-reimplemented pdfplumber`; sources are cached in the git-ignored `tools/.vocab-cache/`; `--offline` reuses the cache; JLPT/TOPIK are re-fetched from the owner's Google Sheets, so editing those sheets means re-running the script). English Chinese meanings come from ECDICT via `zh_meaning()`, which drops computing-jargon senses and moves function-word / common-adverb senses first; `ZH_OVERRIDES` patches the few words it still gets wrong. Sources and licences: `data/vocab/README.md`; each path card credits its list (`path_source`). In `js/quiz.js`, `BUNDLED_SETS` maps set → row kind, `WORD_SET_FAMILIES` groups sets by language for the pickers, `QUIZ_LANG_ORDER` is derived from it, and `loadWordSet(id)` is the one loader (French alone is still read from its Google Sheet, `SHEETS.fr`). `selectWordSet(id)` opens a set; `selectLanguage()` on the quiz page routes 日/韓/中 to the exam page's level pickers and 英文 to `#en-level-card`. The retired general sets (`jp`, `kr`, `en`, `zh`) remain in `LEGACY_SET_IDS` so their mistake-book entries still show. Flashcards pick language + display mode, then a deck (word set); listening picks everything on one page (see Practice tools below); flashcard known/unknown marks stay keyed by language (`lang|mode|word`). Use `isEnglishQuizLang()` (never `=== 'en'`) for English checks. Path progress lives in `path_progress_v2` (reset when the sets were re-ordered).

**Vocabulary quiz (`js/quiz.js`, the largest file)**: the quiz engine. A pasted custom Google Sheet URL still goes through `loadSheetData` and the per-language `parseX(rows)` functions (fixed-width row "stride" parsing — see `parseJapanese`/`parseJapanese2`). Quiz state (mode, current word, score, shuffled order) lives in module-level `let` variables, not a framework state store. Scoring is +10 right, −3 wrong, floored at 0. Mistakes, quiz history, and flashcard "known" words persist to `localStorage` (`quiz_mistakes`, `quiz_records`, `flashcard_known`). Every answer goes through one path in `selectOption()`: grade the SRS card, a miss → `addMistakeEntry()`, a hit → `noteMistakeCorrect()`. A mistake is **repaired** after `MISTAKE_FIX_STREAK` (2) right answers in a row (`entry.fix`; a miss or a timeout resets it); it then gets `fixedAt`, stays in the book struck through for `MISTAKE_FIXED_KEEP_DAYS` (30) and returns to the list if missed again. Badges and home count only open ones (`getActiveMistakes()`). Per-session extras live there too: `comboNow`/`comboBest` ("連對"), `sessionStartedAt`, both reset when a session asks question 1. Show a quiz-page card with `showOnlyQuizCard(id)` (`QUIZ_PAGE_CARDS` lists them all) rather than toggling cards one by one. Score-card sharing renders a `<canvas>` and exports as an image.

**Spaced repetition (`srs_quiz`, in `js/quiz.js`)**: every answered quiz question (any word set, including JLPT/TOPIK/HSK) and every mistake-review answer grades a Leitner card via `gradeSrsQuizCard(entry, correct)` — right moves it up a box (intervals `SRS_INTERVAL_DAYS` = 0/1/3/7/14/30 days), wrong drops it to box 1 due in 10 minutes; a timer timeout counts as wrong. Cards use the **same shape and id as mistake-book entries** (`quizEntryFor(type, answer)` → `{id: lang|word|group, lang, word, answer, hint, group, zct}`), which is what lets the review run on the mistake-review engine: `startSrsQuizReview()` sets `reviewMode = true` with `reviewSource = 'srs'` (vs `'mistakes'`) and up to `SRS_REVIEW_LIMIT` (20) due cards mixed across sets; `nextQuestion()`'s review branch fills wrong options from the same set's cards, then that set's `quiz_cache_<set>`, then near-miss kana for readings. The quiz page's "間隔複習" tool first opens the `#srs-card` page (due count, next batch, 7-day forecast, cards per stage; `startSrsQuizReview('tool')`, whose "返回" comes back there); the home dashboard starts the review directly and "返回" goes home. Anything that starts a new word set must clear the review state (`endReviewState()` in `selectLanguage`/`selectExamSet`), because `showModeSelection()` treats a lingering `reviewMode` as "go to the mistake book". The old flashcard-only SRS (`srs_cards`) was removed in phase 2 of the 2026-10 redesign; its data is simply ignored.

**Satellite sites (no longer linked from here)**: `世界計畫-花火網頁`, `鳴潮-花火網頁`, and `osu-花火網頁` are separate standalone sites/repos in the same family. This site used to host an outbound-links page ("遊戲區") pointing to them, but that page was removed to keep the site focused on vocabulary review and language learning — the satellite sites and their repos are unaffected and still deployed independently.

**Guestbook (`js/guestbook.js`)**: Reads/writes go to a Google Apps Script Web App URL (`GUESTBOOK_API`) acting as a simple JSON store backed by a Google Sheet. POSTs use `mode: 'no-cors'`, so submission success is assumed optimistically (the new message is appended to local state immediately rather than re-fetched).

**Home dashboard (`js/home.js` + `css/home.css`)**: `renderHome()` fills `#page-home` from data `js/quiz.js` already keeps in localStorage — `daily_activity` (`{'Y-M-D': words practised}`, bumped by `logDailyActivity()` on every answered quiz/listening question and every rated flashcard, pruned to 120 days), `calcStreak()` (a day counts if a quiz was finished *or* any word was practised), `last_quiz_set` (set by `startQuiz()`, drives "繼續學習"), `srs_cards`, `quiz_mistakes` and `quiz_records`. The only home-specific key is `daily_goal` (10/20/30/50, cycled by tapping the ring). It re-renders on load, on opening the page and on language switch (`refreshDynamicContent`). To jump into the quiz page from home, `homeResetQuizPage()` clears `currentLang` *before* calling `backToLanguage()` — otherwise a previous JLPT/TOPIK/HSK session makes it bounce to the exam picker.

**Practice tools (`js/practice.js` + `css/practice.css`, redesigned 2026-10)**: the screens around the quiz engine. `renderPracticeHub()` draws the 練習中心 grid under the language buttons (`#quiz-tools`): a tile per tool with what's waiting (due SRS cards, open mistakes, known flashcards, last listening score, words this week) and a 小花火 suggestion for the most urgent; it re-renders via `updateMistakeBadge()` and `refreshDynamicContent()`. The mistake book (`renderMistakeBook`) is a ruled notebook with per-set chips, sort by most-missed / recent / repaired, red dots for times missed and two repair slots; "修復" (`startMistakeRepair`) runs up to 10 open mistakes on the review engine with `reviewSource = 'mistakes'`, re-asking each right answer once more a few questions later (`requeueForRepair`) so one round can repair a word. The stats page shows how much is learned (the best SRS box per word, grouped into 4 stages `SRS_STAGES`: 新學 1 / 學習中 2–3 / 熟悉 4 / 精通 5–6, per word set against its cached word count), a 16-week practice calendar from `daily_activity`, this week vs last week, achievements and recent quizzes. Flashcards: a deck list (`renderFlashcardDecks`, prefs in `flashcard_prefs`) → a 20-card session (the set's 還不熟 words, then unseen ones in list order, topped up with known ones) on a card you flip by tap/space and rate by swiping (pointer events, `FC_SWIPE_PX`) or ← →. The result screen pieces (`resultHeroHtml`, `resultGoalHtml`, `resultHookHtml`) are shared by `showResults()` and the flashcard finish: confetti + 小花火, accuracy / best streak / time, the daily-goal ring, and a reason to come back (cards due now / within 24 h / next batch); "再練錯的字" (`retryWrongWords`) replays the session's misses as a repair round. The listening quiz (in `js/quiz.js`) has a one-page setup remembered in `listening_prefs`, a big play button with 🐢 slow (`speakText(…, {slow})`), and two ways to answer: `choice` (four look-alikes: near-miss kana for Japanese, same-first-letter words otherwise) or typing with letter boxes, a hint that reveals a character for 2 points, and a small-kana key row; a missed word goes to the mistake book as the entry `lessonEntryFor()` builds.

**Accounts & sync (`js/account.js` + `css/account.css`, added 2026-10-04)**: optional sign-in (Google popup, or email + password with sign-up / reset) through Firebase project `hanabi-site` (Spark plan; Auth providers Google + Email/Password; authorized domains include `hanabirn.xyz` and `localhost`; Firestore in `asia-east1` with owner-only rules `match /users/{uid}/{document=**} { allow read, write: if request.auth.uid == uid }`). The web config in `FIREBASE_CONFIG` is public by design. Only the Auth SDK is loaded (dynamic `import()` from gstatic, pinned version in `FIREBASE_SDK`), and only when the account dialog opens or `localStorage.acct_signed_in` says this device was signed in; Firestore is used through its REST API with the user's ID token (`fsRequest`) instead of the 680 KB SDK. Each key in `SYNC_KEYS` is one document `users/{uid}/data/{key}` = `{v: <localStorage string>}`, merged with its own rule (`syncMerge`: unions / newer entry / max, scalars keep this device's value) — on sign-in for every key (`acctFullSync`), afterwards for keys written since (a wrapped `Storage.prototype.setItem` marks them; uploaded `SYNC_DEBOUNCE_MS` after the last change and when the page is hidden). Not synced: 記事本, `quiz_cache_*`, device prefs. Add a key to `SYNC_KEYS` (with a merge rule) when a new feature stores progress worth keeping. Sign-out keeps the device's data; "delete account" removes the cloud docs and then the user (needs a sign-in within the last few minutes). UI: `.account-entry` in the header and the phone More sheet, `#home-account-card` (hidden when signed in), `#account-overlay`. Explained to visitors in privacy.html section 4 (`sa_*` keys in js/privacy.js).

**Learning path (`js/path.js` + `css/path.css`)**: every built-in set (`QUIZ_LANG_ORDER`) opens on a path once loaded (`showSetStart()`; a pasted custom sheet still goes straight to the mode picker). The set is cut **in sheet row order** into levels of `LESSON_SIZE` (10) words, units of `LEVELS_PER_UNIT` (10) shown as `<details>`; inserting rows mid-sheet therefore shifts later words between levels. A level = word preview (`#lesson-card`) then a quiz asking each word once, run on the same review engine as SRS with `reviewSource = 'lesson'` (`lessonEntryFor()` builds entries with the same id/shape as `quizEntryFor()`: JP kanji words → reading, Chinese → English meaning with pinyin hint, else meaning in English when the UI isn't Chinese), so lesson answers also grade SRS cards and wrong ones go to the mistake book. `LESSON_PASS_PCT` (80) unlocks the next level; progress is `localStorage.path_progress = {setId: {done, best}}` (`done` = levels passed in a row). quiz.js hands lesson results/again/back to `lessonResultHtml()` / `lessonAgain()` / `lessonBack()`; "自由練習" (`showFreePractice`) is the old mode picker, whose "返回" (`modeCardBack`) returns to the path.

**Dictionary (`js/dict.js` + `css/dict.css`, `#page-dict`)**: no backend and no keys — three CORS-enabled services called from the browser, each rendering its own section so one failing never blanks the others; a new search aborts the previous one (`AbortController`). Wiktionary REST `page/definition/{word}` gives part of speech + **English** definitions grouped by language code (try the word as typed, then lower-case, then Capitalised — titles are case-sensitive); its HTML is reduced to text via `DOMParser` after dropping `<style>` blocks. Tatoeba `/unstable/sentences` (requires `sort`) gives example sentences with a translation into the site language. MyMemory is a translation memory that mistranslates lone words (食べる → 美食), so the headline translation is the first Wiktionary gloss translated from English (to eat → 吃); only words Wiktionary lacks (many Chinese ones) are sent to MyMemory directly. MyMemory allows ~5,000 chars/day per visitor IP. Attribution for all three is in the page footer (`dict_sources`). Phones reach the page from the "More" sheet. `escHtml()` also escapes `"` because dictionary output goes into `data-*` attributes.

**Alphabet chart (`js/alphabet.js` + `js/alphabet-data.js` + `css/alphabet.css`, `#page-alphabet`)**: a beginner letter chart with tabs for English, hiragana, katakana (both with dakuon / handakuon), Korean (basic + double consonants, basic + compound vowels), 注音 (with pinyin), Russian, French, German (+ Ä Ö Ü ß) and Spanish (+ Ñ). Every entry in `ALPHABETS` is `[glyph, reading, text to speak, example word, word reading, emoji, meaning zh, meaning zh-Hans, meaning en]`, hand-written — edit the data file directly. The text to speak is not always the glyph: Korean jamo say their name (기역) or the vowel syllable (아), 注音 symbols a character with that sound (ㄅ → 玻), Russian/Spanish letters their names, because TTS reads lone symbols unreliably. An empty example word marks a letter that is basically unused (ヂ, ヅ, ヲ). Meanings are only stored in zh / zh-Hans / en (other UI languages get English) and are hidden when the UI language is the tab's own language. `alphaHighlight()` marks the letter inside the example word. Sound goes through `speakText()` (see Speech below). Reached from the desktop nav, the phone "More" sheet and the home page's "剛開始學？" button; the chosen tab is kept in `localStorage['alpha_tab']`.

**Speech (`js/speech.js`)**: every 🔊 on the site — quiz `speakWord()`, the lesson preview, `dictSpeak()`, `alphaSay()` — calls `speakText(text, lang)`; don't create `SpeechSynthesisUtterance`s elsewhere. Browsers list their old built-in voices first (Windows: Microsoft Ayumi, Heami, Hanhan…), which sound robotic, so `ttsCandidates(lang)` ranks the device's voices: exact region first, then Edge's neural "Natural" voices, Chrome's online "Google …" voices, other online voices, built-in last (Chinese only matches its own region — zh-HK is Cantonese). Visitors can override the pick per language (`TTS_LANGS`, zh-TW and zh-CN separately) in the settings panel's voice section (`renderTtsSettings`, re-rendered on `voiceschanged` because Chrome loads voices asynchronously); choices are stored by voice name in `localStorage['tts_voices']` and silently fall back to the automatic pick on a device without that voice. Rate is `TTS_RATE` (0.9). `js/speech.js` loads right after the i18n files.

**Recorded audio (`data/audio/`, built by `tools/build_audio.py`)**: Japanese, Korean and Chinese sound robotic in every browser voice, so the JLPT / TOPIK / HSK words, the alphabet chart's ja/ko/zh entries and the voice-picker samples are pre-rendered with Google Cloud Text-to-Speech (ja Chirp3-HD-Erinome, ko Chirp3-HD-Kore, zh-CN Chirp3-HD-Leda, zh-TW Wavenet-A; Chirp3 is unreliable on a lone kana / hangul syllable, so those use a Neural2 backup voice). One MP3 per text in `data/audio/<ja|ko|zh-CN|zh-TW>/<id>.mp3`, where id = cyrb53 of the NFC-normalised text in base 36 — `audioId()` in `js/speech.js` and `audio_id()` in the script must stay identical. `index.json` per language lists the files plus aliases (simplified → traditional Chinese; a Japanese kanji word → its most basic reading). Japanese kanji words are keyed `word|kana` and spoken from the kana, because one word can have several readings (一日); `speakWord()` passes the kana as `opts.reading`. `speakText()` plays a recording when the index has one and the visitor hasn't chosen a browser voice for that language, else falls back to `speechSynthesis` (also when `play()` is blocked or the file is missing offline). **Don't edit `data/audio/` by hand**: after changing a word list or the alphabet data, re-run `python tools/build_audio.py` (needs `pip install lameenc` and `GOOGLE_TTS_KEY` in the git-ignored `tools/.google-tts.env`; existing files are kept, so only new texts are rendered; `--audition` builds a page to compare voices). Words removed from a list leave their old MP3 behind until deleted.

**Site tour (`js/tour.js` + `css/tour.css`)**: replaced the old 教學手冊 page (removed 2026-10-03). `TOUR_STEPS` lists each step's i18n key (`tour_<key>_title/_text`) and the elements it may spotlight, best first (desktop nav, else the phone tab bar or `#tabbar-more`, whose steps add `tour_in_more`); a step whose targets are all hidden shows a centred card. The spotlight is a fixed box with a huge `box-shadow` that dims everything else; the card goes below the target, else above, else bottom. It starts by itself ~1 s after load only for a first visit (`tourIsFirstVisit`: no `tour_done` and no practice data such as `daily_activity`/`quiz_records`, so existing visitors aren't interrupted) and is replayed via `startTour()` from the settings panel and the phone More sheet. When adding a main feature, add a step in all 9 languages.

**AI assistant (`js/assistant.js` + `css/assistant.css`, Worker in `worker/assistant/`)**: a floating 小花火 (stand-in until the owner draws a character; desktop: above the settings gear on the right, phones: bottom-left above the tab bar) opens a chat panel. The static site can't hold a key, so messages go to the Cloudflare Worker `hanabi-assistant` (`ASSISTANT_API`; `localhost:8787` when the site runs on localhost), which keeps `GEMINI_API_KEY` as a secret, builds 小花火's persona + the site's feature list in `persona()`, and calls Gemini, trying the models in `MODELS` (wrangler.jsonc) in order until one answers: gemini-3.8 / 3.7 / 3.6 / 3.5-flash with thinking off, then gemini-3.5-flash-lite. Each flash model's free tier is only **~20 requests a day** and they often answer 503, so any failure (429 quota, 503, 500) moves on to the next; the lite model has a much larger quota (gemini-2.5-* is closed to new keys). Guards: `ALLOWED_ORIGINS`, a rate-limit binding (8/min per IP), 12 turns × 600 chars. The key's Google project (`hanabi-assistant-510517`) has **billing disabled on purpose** so only the free tier is used — with billing linked, Gemini answers 402 "prepayment credits depleted". Local test: key in the git-ignored `worker/assistant/.dev.vars`, then `wrangler dev --port 8787` from that folder (wrangler is installed in the osu project). The chat is kept in sessionStorage; our own error notices are flagged `err` and never sent. When site features change, update the feature list in `persona()`.

**Tooltips (end of `js/widgets.js`)**: native `title` tooltips are an unstylable white box, so on mouse hover a title moves to `data-tip` and a vermilion `.site-tip` bubble shows it (icon-only buttons get the text as `aria-label`). Keep using `title` / `data-i18n-title` in markup; it's picked up automatically.

**Mascot (小花火)**: the firework mascot is inline SVG (class `hm`, parts `hm-s1/2/3`, `hm-fuse`, `hm-body`, …) in the header brand, the splash and the home hero; its colours live in `css/mascot.css` and follow the theme (the fuse turns light on 墨夜).

**Widgets (`js/widgets.js`)**: Self-contained, DOMContentLoaded-initialized features unrelated to the SPA nav: BGM vinyl player (rotating playlist of external mp3 URLs), the phone "More" sheet (`toggleMoreSheet`/`closeMoreSheet`), and clock + geolocation-based weather (Open-Meteo API).

**Theming (`js/theme.js`)**: Light/dark theme toggled via `data-theme` attribute on `<html>`, persisted to `localStorage['theme']` (first-time visitors follow `prefers-color-scheme`), applied synchronously before `DOMContentLoaded` to avoid flash; `applyTheme()` also updates `<meta name="theme-color">`. The look is "和紙" (washi paper, light) / "墨夜" (ink night, dark): flat paper background, ink text, a single vermilion accent, Noto Serif TC headings and Noto Sans TC body — no glows, gradients or glassmorphism (the old sakura/stars/particles/fireflies were removed in the 2026-10 redesign); the only decoration is a faint 青海波 wave pattern rising from the bottom of the screen (`body::before` in `css/base.css`, colours in `--wave-pattern` in `theme.css`). The floating clock is desktop-only: on phones it covered buttons. All colours are CSS custom properties in `css/theme.css`: prefer the semantic tokens (`--primary`, `--primary-edge`, `--surface`, `--line`, `--edge`, `--ink`, `--success*`, `--danger*`, `--track`, `--font-serif`); the older names (`--accent-pink`, `--text-pink`, …) are kept as aliases so existing rules still work. Buttons are **chunky 3D**: a 2px outline plus a 4px darker "thickness" drawn with `box-shadow: 0 4px 0 var(--edge)` (vermilion buttons use `--primary-edge`), and `:active` does `translateY(4px)` and drops the shadow — box-shadow rather than a border so pressing doesn't change the height and shift the layout. The shared recipe is the "Chunky 3D buttons" block at the top of `css/quiz.css` (`.lang-btn`, `.mode-btn`, `.option-btn`, `.tool-btn`, `.back-btn`, `.next-btn`, `.share-btn`, …). The share card (`shareScoreCard`) is a canvas, which can't read CSS variables, so it hardcodes the light 和紙 palette.

**PWA**: "下載 App" (`.install-entry`: a header button on desktop, an item in the phone More sheet; hidden via `html.is-standalone` when running as the installed app) opens `#install-overlay` (`openInstallHelp()` in `js/widgets.js`): browsers with `beforeinstallprompt` get the real install prompt, the rest (iOS Safari, desktop Safari, Firefox) get add-to-home-screen steps for their platform (`INSTALL_STEPS`). The bottom `#pwa-install-banner` suggests it once (on iOS 8 s after load, never over the site tour); ✕ sets `pwa_install_dismissed`. `manifest.json` + `service-worker.js` (network-first-with-cache-fallback strategy — `fetch` always hits the network and updates the cache, only falling back to cache when offline). Bumping `CACHE_NAME` is necessary when changing the `ASSETS` list, since a stale cached list would keep serving old files to offline visitors.

## Conventions worth knowing

- No JS framework/module system — everything is global functions/variables attached via plain `<script>` tags, and `onclick="..."` attributes in HTML call these global functions directly.
- Chinese (Traditional) is the default/fallback language throughout (`I18N.zh` is the fallback in `t()`).
- HTML entities (`&#x...;`) are used for CJK/emoji text directly in `index.html` markup instead of raw UTF-8 characters in many places (legacy from earlier edits) — matching surrounding style when editing those sections is fine, but new text can be written as plain UTF-8.

## Workflow for feature/dev requests

For any non-trivial dev request, work through these stages in order:

1. **UI/design pass** (only if the request touches the front end): match the 和紙/墨夜 theme — flat cards, chunky 3D buttons, the CSS custom properties in `css/theme.css` (don't hardcode colors; check both themes), the phone layout (≤768px: bottom tab bar, no top nav), and the existing per-feature `css/*.css` split. There's no React/Tailwind/v0 in this project — new UI is plain HTML + CSS, written by hand.
2. **Implementation**: wire up the HTML/CSS/JS following the conventions above (global functions, `onclick=` handlers, i18n keys added to all 9 `i18n/<lang>.js` files, new files registered in `index.html`'s script/link tags and `service-worker.js`'s `ASSETS`).
3. **Verification** (this project has no test suite or build step, so "testing" means): check the changed files for obvious syntax errors, then actually load the change in a browser (e.g. `python -m http.server` from the repo root) and click through the affected feature before calling it done — per the top-level guidance to verify UI changes in a real browser rather than assuming they work.
4. **Final report**: once verified, and after committing/pushing per the user's request, give a short summary of what changed — don't pad it with restated context.
