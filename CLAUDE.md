# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Hanabiの小天地" — a static, single-page personal website (vocabulary quiz app, guestbook, about page) in Traditional Chinese with 9-language i18n (zh/zh-Hans/en/ja/ko/ru/fr/es/de), focused on vocabulary review and language learning. No framework, no build step, no bundler, no package.json. Plain HTML/CSS/JS served directly.

## Running / deploying

There is no build or test command — the repo root is served as-is by **GitHub Pages**.

- The remote is `github.com/hanabirn/hanabirn.github.io` (a GitHub Pages *user site*), served at the custom domain **`https://hanabirn.xyz/`** straight from the `main` branch root. Pushing to `main` is the deploy — there is no CI workflow, no build step, and no `.github/` directory.
- The custom domain is set by the `CNAME` file at the repo root — don't delete or rename it, or GitHub Pages drops the domain. `hanabirn.github.io` 301-redirects to `hanabirn.xyz`, so old links still work. DNS lives in Cloudflare (GitHub's four apex A + four AAAA records) with the **proxy deliberately off**: behind Cloudflare's orange cloud GitHub can't complete its HTTPS certificate challenge.
- Absolute URLs that name the host — the canonical link and OG/Twitter meta tags in `index.html`, `sitemap.xml`, `robots.txt` — use `https://hanabirn.xyz/`. Use that domain (not `hanabirn.github.io`) for any new absolute URL.
- Because the site is served from the domain root, absolute paths (`/icons/...`, `manifest.json`'s `start_url: "/"`) work as-is; no base-path rewriting is needed.
- The site used to be on Netlify (`hanabirn.netlify.app`), which is now paused for exceeding its free usage limits. All Netlify config (`netlify.toml`, the empty `netlify/functions` dir, the local `.netlify` CLI cache) was removed in the 2026-09-24 cleanup, along with the stale `hanabirn.netlify.app` URLs in `index.html`'s OG/Twitter meta tags. Don't reintroduce Netlify-specific files or URLs — with one deliberate exception: Netlify built `hanabirn.netlify.app` from this repo's `main` (since 2026-10-08 its builds are **Stopped** in the Netlify dashboard so pushes don't use its free credits — the last deploy, with `_redirects`, keeps serving; changing `_redirects` means switching builds back to Active first), and visitors kept using it (an iPhone home-screen app installed from there got 403 from the AI Worker, which only allows `hanabirn.xyz`), so the root `_redirects` file 301s every path there to `https://hanabirn.xyz/…?from=netlify` (added 2026-10-03 at the owner's request); that marker makes `js/widgets.js` show the "網站搬家囉" notice (`#moved-overlay`: delete the old home-screen app and install again, offering `openInstallHelp()`) and is then removed from the address bar. Progress stored under the Netlify origin can't follow; the notice says so. GitHub Pages runs Jekyll, which skips `_`-prefixed files, so it has no effect on the real site.
- There is no linter or test suite configured.

## Architecture

**Single-page app shell**: `index.html` contains every "page" (`#page-home` — the default — plus `#page-quiz`, `#page-notes`, `#page-about`, `#page-guestbook`, `#page-feedback`) as sibling `<div>`s toggled via `display: none/block`. `switchPage(page, el)` in `js/quiz.js` handles navigation — no router, no URL state. Every page has a `.nav-btn[data-tab=…]` on desktop **and** in the phone UI. **Navigation (reorganised 2026-10-10 to keep the screen simple):** the desktop header is one row — brand | `.main-nav` | controls (language, theme switch, account pill, ☰) — and when that doesn't fit (long languages, narrower screens) `headerFit()` in `js/widgets.js` adds `.nav-below` and the nav takes a second row. `.main-nav` holds 首頁 / 單字測驗 / 複習 (2026-10-17; it was 檢定考試, now a tab of the 單字 page) and two dropdowns (`.nav-group`, opened by hover with a mouse or a click: `toggleNavGroup()`): **學習 ▾** (`#nav-group-learn`: 文法, 閱讀, 聽解) and **工具 ▾** (`#nav-group-tools`: 字典, 字母表, 記事本), each item with a one-line description (`nav_<page>_desc`). The ☰ (`#site-menu`, `toggleSiteMenu()`) holds 更新內容, the tour, 下載 App, 留言板, 建議&改進, 關於我, the BGM player (its markup lives there, laid out by `.menu-bgm`), 顯示設定 and 重新整理 — so the only floating button left on desktop is 小花火 (the clock widget and the floating settings / reload buttons were removed). A dropdown gets `.has-active` when one of its pages is open. Phones (≤768px): the header keeps language + an icon-only account button; the bottom `.tabbar` is 首頁 / 單字 / 複習 / **學習** / 更多 — 學習 opens `#learn-sheet` (three cards with progress, `renderLearnSheet()` counting passed items in `grammar_progress` / `reading_progress` / `listening_progress`), 更多 opens `#more-sheet`, a grid in groups (工具 / 網站 / 交流) plus a quick row (深色模式, 背景音樂, 顯示設定, 重新整理). `LEARN_TABS` / `MORE_TABS` in `js/quiz.js` say which tab lights up. Changelog: `js/updates.js`, the `SITE_UPDATES` popup (760px wide on computers, a ✕ in a sticky title row — on phones it replaces the 關閉 button), `UPDATES_PER_PAGE` (4) entries a page with 上一頁 / 下一頁 and ← → — add an entry in all 9 languages when shipping something visible; a dot (`.updates-dot`, on the ☰, its item, the 更多 tab and its tile) shows until it's opened. `switchPage()` sets `.active` by `data-tab`, not on the clicked element, so all copies stay in sync, and tab visibility (`applyTabVisibility`) hides every copy (and a dropdown / the 學習 tab whose pages are all hidden). It shows a page by clearing its inline `display` (not setting `block`, so a page's CSS can make it a grid) and puts the page on `body[data-page]`; `css/base.css` uses that to widen the alphabet, dictionary and quiz pages to 1180px on screens ≥1024px (on the quiz page only `#path-card` takes the width). Desktop layouts there: the alphabet shows 6 cards a row (kana as a 5-column 五十音 chart with `.alpha-blank` gaps), the dictionary is a 2-column grid (`#dict-results` is `display: contents`; examples on the right), and the path shows the picked unit's levels beside a sticky unit list (`.path-wide`; phones keep the `<details>` accordion, `.path-accordion`). Home is locked visible. There is no guide page any more: new visitors get the tour below. All CSS is split by feature into `css/*.css` and all linked individually in `<head>` (no bundling), and `js/*.js` files are loaded as plain `<script>` tags in a specific dependency order at the bottom of `<body>` (theme → mascot → PapaParse CDN → `js/i18n.js` → the 9 `i18n/<lang>.js` dictionary files → speech → quiz → learnlang → path → home → practice → account → dict → alphabet data → alphabet → grammar → reading → listening → updates → tour → rails → guestbook → notes → feedback → widgets). New JS files must be added to that script list, to `service-worker.js`'s `ASSETS` cache list, and CSS files to both `<head>` and `ASSETS`.

**i18n (`js/i18n.js` + `i18n/<lang>.js`)**: `js/i18n.js` only declares `const I18N = {}` plus the shared logic (`applyLang`, `setSiteLang`, `t`); the actual translations live in one file per language — `i18n/zh.js`, `i18n/zh-Hans.js`, `i18n/en.js`, `i18n/ja.js`, `i18n/ko.js`, `i18n/ru.js`, `i18n/fr.js`, `i18n/es.js`, `i18n/de.js` — each just assigning a flat dict to `I18N.<lang>` (e.g. `I18N.en = {...}`; Simplified Chinese needs bracket syntax, `I18N['zh-Hans'] = {...}`). `zh-Hans.js` was generated from `zh.js` with OpenCC (`tw2sp`) and then hand-fixed for mainland wording (单词, 复制, 置顶, 离线, 导航栏, Google 表格…) — when adding a zh key, write the Simplified version by hand in the same style rather than a character-by-character conversion. These must load as `<script>` tags *after* `js/i18n.js` (which declares `I18N`) and *before* any script that calls `t()`/`applyLang()` at top level. `applyLang(lang)` walks all `[data-i18n]` / `[data-i18n-placeholder]` elements and swaps text/placeholders; `t(key, params)` is used for dynamically-generated strings (e.g. `t('load_success', {n: 5})`, using `{n}`-style placeholder substitution). Adding UI text means adding the key to **all 9** `i18n/<lang>.js` files. `setSiteLang()`/`applyLang()` persists choice to `localStorage['site_lang']` and calls `refreshDynamicContent()` (in `js/quiz.js`) so already-rendered dynamic content (quiz menus) re-renders in the new language.

**Word sets (`data/vocab/*.json`, built by `tools/build_vocab.py`)**: the quiz, paths, flashcards and listening tool load bundled, graded word lists — `en_jh` / `en_sh` (大考中心 7000 Level 1–2 / 3–6), `en_toeic` (TSL), `en_toefl` (ECDICT toefl tag minus the 國中 words), `jlpt_n5`…`jlpt_n1` and `topik_1`…`topik_4` (the owner's own sheets; since 2026-10-10 the JLPT levels are checked against the tanos.co.uk lists (CC BY, `jlpt_reference()`): an entry the reference puts at an easier level moves there, a word in two levels stays only in the easiest, and a rarer reading of a common kanji (人 じん) or 1–2 unplaceable kana (だけ) goes to the end of its level — `JLPT_KEEP` / `JLPT_MOVE` hold the owner's overrides, and each run writes a review page, tools/.mockups/jlpt_moves.html), `hsk_1`…`hsk_7` (HSK 3.0, Nov-2025 revision; 7 = 7–9). Each list is ordered easy-first by frequency, which is what makes the first path levels easy. The **topic sets** `tp_<ja|ko|en|zh|fr|ru|es|de>_<topic>` (10 topics × 40 words = 4 levels each: greetings, food, home, shopping, transport, travel, weather, school, work, health; added 2026-10-04, French and Russian 2026-10-08, Spanish and German 2026-10-09 — French rows `le chat<TAB>m.<TAB>zh<TAB>en` and Spanish `el gato<TAB>m.<TAB>zh<TAB>en` (plurals as los / las) like the CEFR sets, Russian `слово<TAB>сло́во<TAB>zh<TAB>en`) are the exception: hand-written by Claude, approved by the owner, in `tools/topics/<lang>.tsv` (`## <topic>` headers, `word<TAB>reading<TAB>meaning<TAB>english`, edit those files directly) and kept in the file's order; `build_vocab.py --only topics` turns them into JSON. **French, Russian, Spanish and German** are graded by CEFR, A1–C1, on the 單字 page's 檢定等級 tab (`CEFR_LANGS`): `fr_a1`…`fr_c1` from FLELex (the "Beacco" version, which gives every lemma a level; replaced the owner's French sheet — `fr` is now in `LEGACY_SET_IDS`) and `ru_a1`…`ru_c1` from the Russian Kelly list, `es_a1`…`es_c1` from ELELex (per-level frequencies, not levels: a word's level is the first by which it has turned up in 2 texts; skip noise in `ES_SKIP`, the basic numbers are added by hand in `ES_NUMBERS`), `de_a1`…`de_c1` from DAFlex (same levelling; DAFlex has no genders, so gender and plural come from Wiktionary and German rows are `[der Hund, m. · Pl. Hunde, zh, en]`; feminine nominalised adjectives such as die Beste are dropped as duplicates, `DE_SKIP` / `DE_KEEP_FEM`). These lists lack translations, so `build_vocab.py --only fr|ru|es|de` (needs `pip install xlrd` for Kelly's .xls) streams Wiktionary's kaikki.org dump (≈0.6 / 0.9 GB, never saved — only the entries for listed words go into `tools/.vocab-cache/kaikki_<lang>.json`; Russian is matched with ё folded to е because Kelly writes еще) for English glosses, French genders and Russian stress marks, and has **Gemini** write the Chinese meanings (`gemini_meanings`: batches of 100 with a JSON schema, cached in `tools/.vocab-cache/gemini_<lang>.json`, so a re-run only asks for new words; it uses the assistant's key from `worker/assistant/.dev.vars` but only models the assistant doesn't — `GEMINI_MODELS` — because quotas are per model; when the free quota runs out it stops and the next run carries on). Fix a bad meaning in `ZH_FIX_FR` / `ZH_FIX_RU` / `ZH_FIX_ES` / `ZH_FIX_DE` (also used for words Gemini can't translate alone: articles, clitics) and, when Wiktionary picked a homonym, the English in `EN_FIX_FR` / `EN_FIX_RU` / `EN_FIX_ES` / `EN_FIX_DE`; for Spanish (and German) `learner_glosses()` drops slang senses (amigo: penis) and turns "alternative form of X" / "ellipsis of X" / "clipping of X" into X's meaning, looking X up in its own cache `kaikki_<es|de>_alt.json`; drop list noise (names, forms filed as words) in `FR_SKIP`. A re-run with everything cached makes no Gemini calls. Kept: words Wiktionary knows in that part of speech, French nouns only with a gender, each word once at its lowest level, most frequent first. French rows are `[le chat, m., zh, en]` (article added except before h, months and days; the gender is the reading), Russian `[молоко, молоко́, zh, en]` (the stressed form as reading). `isFrenchQuizLang()` / `isRussianQuizLang()` / `isSpanishQuizLang()` / `isGermanQuizLang()` cover them; `wordSetName()` names them "法文 A1"; they are the 檢定等級 tab of the 單字 page when French / Russian / Spanish / German is the learning language. Listening typing accepts a French, Spanish or German noun without its article and Russian without ё. Chinese (`zh.tsv`) is written as `traditional<TAB>pinyin<TAB>english[<TAB>simplified]` in Taiwan wording and readings: the script converts simplified with OpenCC `tw2s` (character by character, so 計程車 → 计程车, not 出租车) unless the 4th column gives it, and bopomofo from the space-separated pinyin with `pypinyin`, giving HSK-shaped rows. **Don't edit the JSON by hand** — fix `tools/build_vocab.py` and re-run it (`pip install wordfreq opencc-python-reimplemented pdfplumber pypinyin`; sources are cached in the git-ignored `tools/.vocab-cache/`; `--offline` reuses the cache; JLPT/TOPIK are re-fetched from the owner's Google Sheets, so editing those sheets means re-running the script). English Chinese meanings come from ECDICT via `zh_meaning()`, which drops computing-jargon senses and moves function-word / common-adverb senses first; `ZH_OVERRIDES` patches the few words it still gets wrong. Sources and licences: `data/vocab/README.md`; each path card credits its list (`path_source`). In `js/quiz.js`, `BUNDLED_SETS` maps set → row kind, `WORD_SET_FAMILIES` groups sets by language for the pickers, `QUIZ_LANG_ORDER` is derived from it, and `loadWordSet(id)` is the one loader (French alone is still read from its Google Sheet, `SHEETS.fr`). `selectWordSet(id)` opens a set. **The 單字 page (`#page-quiz`'s `#lang-card`, merged 2026-10-17, proposal C) shows the header's learning language (js/learnlang.js) in two tabs** — 主題 (a tile per topic with its path progress) and 檢定等級 (the graded lists of `WORD_SET_FAMILIES[code]` that aren't topics: JLPT, TOPIK, HSK, English 國中/高中/多益/托福, CEFR), drawn by `renderWords()`, tab in `wordsTab` / `localStorage.words_tab`; no language chosen yet → `learnChooseHtml()`. The separate 檢定 page (`#page-examquiz`), the `#topic-card` and the region → language pickers are gone: `switchPage('examquiz')` and the home page's exam shortcuts (`homeOpenExam`, which also sets the learning language) open the 檢定等級 tab (`openWords('levels')`), and a set's 返回 (`backToLanguage`) lands on the tab it came from. Its navigation slot is **複習** now (`data-tab="review"`, `openReview()` → the 間隔複習 page, which has a row to the mistake book): it isn't a page of its own, so `quizNavMark()` lights 單字 or 複習 depending on what the quiz page shows (`quizReviewShown()`), tapping 單字 while a review is on screen goes back to the word sets, and `.review-badge` shows the cards due (`updateReviewBadge()`, run by `updateMistakeBadge()`). `LANG_REGIONS` (js/quiz.js) now only groups the learning-language menu. `TOPIC_IDS` / `TOPIC_EMOJI` / `TOPIC_FILE_LANG` / `topicOf()` describe the topic sets (they are added to `BUNDLED_SETS` and, after the graded sets, to `WORD_SET_FAMILIES`); show a set's name with `wordSetName(id)` ("日文・吃飯" for a topic, else `t('quiz_<id>')`), never `t('quiz_' + id)` directly. `backToLanguage()` returns a topic set to its topic card. The retired general sets (`jp`, `kr`, `en`, `zh`) remain in `LEGACY_SET_IDS` so their mistake-book entries still show. Flashcards pick language + display mode, then a deck (word set); listening picks everything on one page (see Practice tools below); flashcard known/unknown marks stay keyed by language (`lang|mode|word`). Use `isEnglishQuizLang()` (never `=== 'en'`) for English checks. Path progress lives in `path_progress_v2` (reset when the sets were re-ordered).

**Vocabulary quiz (`js/quiz.js`, the largest file)**: the quiz engine. A pasted custom Google Sheet URL still goes through `loadSheetData` and the per-language `parseX(rows)` functions (fixed-width row "stride" parsing — see `parseJapanese`/`parseJapanese2`). Quiz state (mode, current word, score, shuffled order) lives in module-level `let` variables, not a framework state store. Scoring is +10 right, −3 wrong, floored at 0. Mistakes, quiz history, and flashcard "known" words persist to `localStorage` (`quiz_mistakes`, `quiz_records`, `flashcard_known`). Write progress with `storeSet(key, value)` (top of `js/quiz.js`), not a bare `localStorage.setItem`: when the ~5 MB quota is full it drops the re-downloadable `quiz_cache_*` word-list copies (biggest first, keeping the current set) until the write fits, so progress is never silently lost and a result screen never throws. **Japanese reading options** are look-alike kana as in the JLPT (`generateSimilarReadings()` / `kanaSlips()`: a long vowel added, dropped or moved, っ, a dakuten, ゃゅょ; a changed vowel only for short words; `KANA_ALSO_RIGHT` keeps out another right reading such as にっぽん) — in the free quiz, path lessons, reviews and the listening tool; the Discord bot uses a copy, `worker/discord/src/kana.js`, with its seeded rand — keep the two alike. Every answer goes through one path in `selectOption()`: grade the SRS card, a miss → `addMistakeEntry()`, a hit → `noteMistakeCorrect()`. A mistake is **repaired** after `MISTAKE_FIX_STREAK` (2) right answers in a row (`entry.fix`; a miss or a timeout resets it); it then gets `fixedAt`, stays in the book struck through for `MISTAKE_FIXED_KEEP_DAYS` (30) and returns to the list if missed again. Badges and home count only open ones (`getActiveMistakes()`). Per-session extras live there too: `comboNow`/`comboBest` ("連對"), `sessionStartedAt`, both reset when a session asks question 1. Show a quiz-page card with `showOnlyQuizCard(id)` (`QUIZ_PAGE_CARDS` lists them all) rather than toggling cards one by one. Score-card sharing renders a `<canvas>` and exports as an image.

**Spaced repetition (`srs_quiz`, in `js/quiz.js`)**: every answered quiz question (any word set, including JLPT/TOPIK/HSK) and every mistake-review answer grades a Leitner card via `gradeSrsQuizCard(entry, correct)` — right moves it up a box (intervals `SRS_INTERVAL_DAYS` = 0/1/3/7/14/30 days), wrong drops it to box 1 due in 10 minutes; a timer timeout counts as wrong. Cards use the **same shape and id as mistake-book entries** (`quizEntryFor(type, answer)` → `{id: lang|word|group, lang, word, answer, hint, group, zct}`), which is what lets the review run on the mistake-review engine: `startSrsQuizReview()` sets `reviewMode = true` with `reviewSource = 'srs'` (vs `'mistakes'`) and up to `SRS_REVIEW_LIMIT` (20) due cards mixed across sets; `nextQuestion()`'s review branch fills wrong options from the same set's cards, then that set's `quiz_cache_<set>`, then near-miss kana for readings. The quiz page's "間隔複習" tool first opens the `#srs-card` page (due count, next batch, 7-day forecast, cards per stage; `startSrsQuizReview('tool')`, whose "返回" comes back there); the home dashboard starts the review directly and "返回" goes home. Anything that starts a new word set must clear the review state (`endReviewState()` in `selectWordSet`), because `showModeSelection()` treats a lingering `reviewMode` as "go to the mistake book". The old flashcard-only SRS (`srs_cards`) was removed in phase 2 of the 2026-10 redesign; its data is simply ignored.

**Satellite sites (no longer linked from here)**: `世界計畫-花火網頁`, `鳴潮-花火網頁`, and `osu-花火網頁` are separate standalone sites/repos in the same family. This site used to host an outbound-links page ("遊戲區") pointing to them, but that page was removed to keep the site focused on vocabulary review and language learning — the satellite sites and their repos are unaffected and still deployed independently.

**Guestbook (`js/guestbook.js`, Worker side `worker/assistant/src/guestbook.js`, rebuilt 2026-10-08)**: served by the `hanabi-assistant` Worker at `/guestbook` (`GUESTBOOK_API`; `localhost:8787` locally) and stored in its KV namespace `GUESTBOOK` (`list` = all messages newest first, `u:<uid>` = that account's message), which only the Worker can write — so the rules really hold. Posting needs a site account: the client sends the Firebase ID token, the Worker checks it with the Identity Toolkit (`FIREBASE_API_KEY`, the public web key), refuses email accounts whose address isn't verified (the gate offers 寄驗證信 via `sendEmailVerification`), allows **one message per account** (the mark stays even if the owner deletes the message) and has Gemini (`moderate()`, lite model first, JSON schema) refuse violence, politics, sexual content, hate, spam/ads and personal data — failing closed (`moderation_busy`) when no model answers. Friendly mentions of a country ("台灣加油") are explicitly not politics. `renderGuestbookGate()` shows sign in / verify / already posted / the form; `account.js` calls `guestbookOnUser()` on sign-in changes. The owner deletes a message with `DELETE /guestbook/<id>` + `Authorization: Bearer <ADMIN_TOKEN secret>`. The old Apps Script guestbook (5 messages) was imported into KV; the 建議&改進 page still uses Apps Script.

**Home dashboard (`js/home.js` + `css/home.css`)**: `renderHome()` fills `#page-home` from data `js/quiz.js` already keeps in localStorage — `daily_activity` (`{'Y-M-D': words practised}`, bumped by `logDailyActivity()` on every answered quiz/listening question and every rated flashcard, pruned to 120 days), `calcStreak()` (a day counts if a quiz was finished *or* any word was practised), `last_quiz_set` (set by `startQuiz()`, drives "繼續學習"), `srs_cards`, `quiz_mistakes` and `quiz_records`. The only home-specific key is `daily_goal` (10/20/30/50, cycled by tapping the ring). **The 今天 card (`#home-today`, proposal B 2026-10-17)** replaced the goal card, the 繼續學習 button and the review / mistake cards: `homeTodaySteps()` lists, in order, the due SRS cards (a batch of `SRS_REVIEW_LIMIT`, only once the visitor has cards), the daily goal and — while any are open — the mistake book; done steps get a tick, and `#home-continue` (`homeTodayGo()`) goes to the first one not done (all done → keep practising the last set). Below it 繼續上次的 (`#home-recent`): the recent word sets plus the 文法 / 閱讀 / 聽解 level last opened in the learning language (`homeLearnChips()`, from `learn_last_levels`, fetching those pages' index.json when not loaded yet); 剛開始學？ (`#home-beginner`) only shows before any practice. The exam shortcuts were removed (the 單字 page's 檢定等級 tab). It re-renders on load, on opening the page and on language switch (`refreshDynamicContent`). To jump into the quiz page from home, `homeResetQuizPage()` clears `currentLang` *before* calling `backToLanguage()` — otherwise a lingering set or review sends 返回 elsewhere.

**Practice tools (`js/practice.js` + `css/practice.css`, redesigned 2026-10)**: the screens around the quiz engine. `renderPracticeHub()` draws the 練習中心 grid under the language buttons (`#quiz-tools`): a tile per tool with what's waiting (due SRS cards, open mistakes, known flashcards, last listening score, words this week) and a 小花火 suggestion for the most urgent; it re-renders via `updateMistakeBadge()` and `refreshDynamicContent()`. The mistake book (`renderMistakeBook`) is a ruled notebook with per-set chips, sort by most-missed / recent / repaired, red dots for times missed and two repair slots; "修復" (`startMistakeRepair`) runs up to 10 open mistakes on the review engine with `reviewSource = 'mistakes'`, re-asking each right answer once more a few questions later (`requeueForRepair`) so one round can repair a word. The stats page shows how much is learned (the best SRS box per word, grouped into 4 stages `SRS_STAGES`: 新學 1 / 學習中 2–3 / 熟悉 4 / 精通 5–6, per word set against its cached word count), a 16-week practice calendar from `daily_activity`, this week vs last week, achievements and recent quizzes. Flashcards: a deck list (`renderFlashcardDecks`, prefs in `flashcard_prefs`) → a 20-card session (the set's 還不熟 words, then unseen ones in list order, topped up with known ones) on a card you flip by tap/space and rate by swiping (pointer events, `FC_SWIPE_PX`) or ← →. ## Conventions worth knowing

- **Phone layout (≤768px, 2026-10-17)**: `main` has a 16px gutter and a page's outer card (`.lang-card` / `.mode-card` / `.quiz-card` / `.guestbook-card` / `.about-card` directly inside `#page-*`, except home) loses its frame (css/responsive.css), so content uses the screen width; button groups that wrapped unevenly are even grids (alphabet tabs 3 × 3, dictionary languages 4 × 2, the More sheet's groups all 4 columns); 小花火's chat button sits whole in the bottom-left corner and slides away while scrolling down; a site name too long for the phone header shows as "Hanabi" (`.brand-short`, `headerFit()`).
- No JS framework/module system — everything is global functions/variables attached via plain `<script>` tags, and `onclick="..."` attributes in HTML call these global functions directly.
- Chinese (Traditional) is the default/fallback language throughout (`I18N.zh` is the fallback in `t()`).
- HTML entities (`&#x...;`) are used for CJK/emoji text directly in `index.html` markup instead of raw UTF-8 characters in many places (legacy from earlier edits) — matching surrounding style when editing those sections is fine, but new text can be written as plain UTF-8.

## Workflow for feature/dev requests

For any non-trivial dev request, work through these stages in order:

1. **UI/design pass** (only if the request touches the front end): match the 和紙/墨夜 theme — flat cards, chunky 3D buttons, the CSS custom properties in `css/theme.css` (don't hardcode colors; check both themes), the phone layout (≤768px: bottom tab bar, no top nav), and the existing per-feature `css/*.css` split. There's no React/Tailwind/v0 in this project — new UI is plain HTML + CSS, written by hand.
2. **Implementation**: wire up the HTML/CSS/JS following the conventions above (global functions, `onclick=` handlers, i18n keys added to all 9 `i18n/<lang>.js` files, new files registered in `index.html`'s script/link tags and `service-worker.js`'s `ASSETS`).
3. **Verification** (this project has no test suite or build step, so "testing" means): check the changed files for obvious syntax errors, then actually load the change in a browser (e.g. `python -m http.server` from the repo root) and click through the affected feature before calling it done — per the top-level guidance to verify UI changes in a real browser rather than assuming they work.
4. **Final report**: once verified, and after committing/pushing per the user's request, give a short summary of what changed — don't pad it with restated context.
